# Security

Version 0.27.0. These are the limits that are actually in the code across `crates/`, `ui/`, and `engines/` in this repository. Each tab has its own `--renderer` process, and the window process fetches and paints (or draws from the renderer's checked `RenderedFrame` when that switch is turned on in `anvil://security`).

Use the private security advisory form on this repository and state which engine or component the problem is in:

https://github.com/buntatoes/anvil-browser/security/advisories/new

Do not put the details in a public issue.

## What is on

- Linux: `PR_SET_NO_NEW_PRIVS`, core dumps off, `SIGXFSZ` ignored (so zero-file-size limits return `EFBIG` rather than terminating the process), and an attempt to cap virtual address space (`RLIMIT_AS`) at 256 GiB on 64-bit Linux for the window process (accommodating GPU driver virtual reservations while `--renderer` strictly enforces 256 MiB and exits if that cap does not stick). When `bwrap` or `unshare` is present and passes the startup self-test, `--renderer` also runs in isolated user, pid, network, IPC, UTS, and mount namespaces (read-only `/usr` under `bwrap`; `prlimit` caps open files at 256 and file size at 0).
- Each tab gets its own `--renderer` process the first time it opens an http, https or local page, and keeps it for later pages in that tab. It starts with an empty environment and `/` as its folder on Linux, so it doesn't get `DISPLAY` or anything else from the window's environment, and it has 5 seconds to say hello in the right protocol version. The document is parsed and its scripts run in the renderer, and the window waits at most 5 seconds for each answer. Messages use the binary format in `anvil_sandbox::wire`, with a size cap on every field and a navigation id on every request and answer. The window process sends the session cookie jar on the GET or POST and stores `Set-Cookie`. The renderer does not receive the jar. The window paints the returned document only when the renderer says it finished. A renderer that times out, exits, sends a bad frame, or answers for another tab or navigation is killed, the tab shows an error page without that document, and the next page in that tab starts a new renderer. After three such crashes in a minute, that tab shows an error page instead of starting another one, until the oldest crash is a minute old. Between pages, each renderer gets a heartbeat every 5 seconds and again before its next page: it has to answer a ping, and on Linux it is killed if it has used more than 1 second of CPU since it last finished a page. On Linux, the idle renderers of one window also have to fit in 1 GiB of resident memory together. Over that, idle renderers of background tabs are ended, the one left alone longest first, until the rest fit. The tab in front is never ended for this, and a tab whose renderer was ended starts a new one for its next page. While it works on a page, a renderer on Linux may use at most 20 seconds of CPU in the tab in front and 10 seconds in a background tab, or it is killed. Waiting on fetches doesn't count toward that. Closing a tab ends its renderer. `anvil://` pages are built in the window process. The renderer turns its own networking off when it starts and never holds cookies. For each linked script, stylesheet, image, and script `fetch()` it asks the window, which applies the shield, mixed content, HTTPS-only with your exceptions, the cross-origin resource policy, and the same-origin rule for `fetch()`, and sends back only the status, the content type and the body. Only script `fetch()` sends and stores cookies, in the window's jar. A renderer may ask for at most 512 fetches for one page, up to 48 MiB of decoded images, and gets 60 seconds for the whole page, fetches included, or it is killed. Video and map tiles stay with the window. A local page's own scripts are still read from disk by the renderer, and unless `bwrap` confinement is active on Linux, it still has your file access.
- Windows: a job object on the window process with a memory cap. The worker job, when used, also limits process count and UI rights, and renderers start from a copy of the executable with a low integrity label.
- A panic in `execute_isolated`, or in a background page load, is caught.
- HTTPS on Linux goes through OpenSSL, with certificate checks. Windows uses Schannel.
- A page whose certificate is untrusted, expired, or for another name gets its own certificate page (still `ERROR ID-17`) that says which of the three it was. Nothing is sent to the site: the connection stops before any request. Other TLS failures keep the plain navigation error page. The page never goes on by itself. Its two links need this run's key: one lets that host's certificate problems through until the browser closes and is never saved, the other saves `allow_insecure_tls` for the host in site permissions, where it can be undone. Either one covers that exact host only, not the hosts under it. A host that must use HTTPS (HSTS, learned or built in) gets no way past: the page shows no links, keyed links for it are refused, and an exception saved before the site sent HSTS stops counting. Only those three problems are let through for such a host; any other failed check still stops the connection, and sessions opened that way are pooled apart from checked ones. When HTTPS-only upgrades an `http` address, a certificate problem on it still shows the HTTPS-only page. Exceptions work on Linux only; on Windows the certificate page has no way past.
- On Linux, the TLS handshake asks OpenSSL to offer X25519MLKEM768 first, then X25519, P-256, and P-384, with key shares for the hybrid and X25519. If this OpenSSL doesn't accept that list (it needs 3.5), a classical list is used, and if that fails too, OpenSSL's own defaults. A server without the hybrid gets a classical group. On Windows, Schannel negotiates TLS and queries `SECPKG_ATTR_CIPHER_INFO` / `SECPKG_ATTR_CONNECTION_INFO` after the handshake. The group the handshake really used is read back from OpenSSL or Schannel and shown on `anvil://security` for the last 16 connections made by the window process. A connection is only called post-quantum when that group includes ML-KEM. Tab renderers make no connections of their own. In addition, `anvil-net::pqc_tls13` has a self-contained RFC 8446 TLS 1.3 record and handshake state machine (`Tls13Stream`, `Tls13ClientHandshaker`, `Tls13ServerHandshaker`, `Tls13Session`) built on `anvil-pqc` and `anvil-cipher`, for `X25519MLKEM768` (`0x11EC`) and `X25519` (`0x001D`) key shares, TLS 1.3 `HKDF-SHA256` traffic and application keys, and `AES-256-GCM` record sealing and opening. Page loads don't use it: every real connection goes through OpenSSL or Schannel. Its self-test (`verify_pqc_hybrid_self_test`) runs once, before the first HTTPS connection, and if it fails no HTTPS connection is made.
- Over `https`, both Linux (OpenSSL) and Windows (Schannel `SECBUFFER_APPLICATION_PROTOCOLS`) offer HTTP/2 (`h2`) and HTTP/1.1 (`http/1.1`) through ALPN, and use HTTP/2 when the server picks it. Live GET requests reuse origin-keyed connections (`connection_pool_stats`): over HTTP/2, `H2ClientSession::exchange` reuses pooled sessions across odd stream IDs (`1, 3, 5, ...`) and `fetch_batch` multiplexes same-origin `<link rel="stylesheet">` and `<img>` batches through `H2ClientSession::exchange_multiplexed`; over plain `http`, keep-alive sockets (`Content-Length` and `Transfer-Encoding: chunked` without `Connection: close`) are returned to the origin pool, checked with a non-blocking 1-byte `peek` (`is_pooled_stream_alive`) before reuse to discard peer-closed or dirty sockets, and transparently retried on a fresh connection if the peer closed an idle socket. Server push is turned off. Frames over 16 KiB, header blocks over 256 KiB, decoded header lists over 640 KiB, and bodies over the 80 MiB raw cap (160 MiB decompressed) are refused. Cookie and Authorization fields are never stored in the HPACK tables. If the server asks for HTTP/1.1 or refuses the stream before starting it, the request is sent again over HTTP/1.1 on a new connection. Plain `http` stays on HTTP/1.1.
- HTTPS-only mode, when on, sends every `http` request as `https`: the page, its redirects, and its images, stylesheets, and scripts, in the window, including the fetches it makes for a tab renderer. If the `https` request can't connect or its certificate fails, the tab shows a warning page and nothing is sent over plain `http`. The only way to use plain `http` in this mode is to allow that site, from the warning page or from `anvil://settings/permissions`. An allowed site also covers the hosts under it.
- `anvil://settings/permissions` keeps JavaScript (follow the main switch, allow, or block), cookies (allow or block), and plain HTTP (for HTTPS-only) per site, at most 512 sites. A rule covers the hosts under it, and the longest match wins. Blocked cookie hosts never store or send cookies, and their stored cookies are removed. Changes from that page carry a key made fresh each time the browser starts. A web page can link to an `anvil://` address but can't read the key, so a change without it is ignored. The switches and buttons on `anvil://settings`, `anvil://history`, `anvil://downloads`, and `anvil://home` need the same key. A web page's links and form actions can't point at `anvil://` addresses at all, and an `anvil://` address without the key only shows the page.
- `anvil://settings/scripts` lists the `.js` files in the `userscripts` folder next to `profile.anvil`. New files start off, and turning one on needs the same key. The profile keeps only the file names that are on, never the script text. A file runs only on `http` and `https` pages that one of its `// @match` lines covers, never on `anvil://` pages, and not where JavaScript is off for the site, by the main switch or a site rule. It is added to the page as one more inline script after the page's own, so it runs in the tab's renderer with the page's Content-Security-Policy, the 256 KiB script cap, the 512 fetch cap and the 60 second page limit, and its `fetch()` goes through the window like any page script. It gets no extra API: a file that asks for `@grant` anything but `none` doesn't run. Files over 256 KiB, links, and anything that isn't a plain `.js` name are skipped. Nothing is downloaded or updated from the network.
- Cookies are partitioned by the site of the top-level page (the last two labels of its host, or the whole address for an IPv4 host). A cookie is only sent while the top-level page is on the same site it was set under. Cookies saved before partitioning go into their own site's partition.
- Linux profiles (`profile.anvil`, including bookmarks, history, cookies, HSTS, settings, site permissions, and origin-partitioned `localStorage`) are AES-256-GCM from `anvil-cipher`. The key is `profile.key` (mode 0600) in the same directory, written before the profile. Windows profiles use DPAPI. `sessionStorage` is not in the profile. Each origin can store 64 KiB of `localStorage` or `sessionStorage` key and value bytes. A write past that cap leaves the previous value in place.
- Saved logins are kept in `logins.anvil`, next to the profile and never inside it, sealed the same way as the profile (AES-256-GCM with `profile.key` on Linux, DPAPI on Windows). If the seal can't be made, nothing is written. If `logins.anvil` can't be opened at startup, the window shows `ERROR ID-31` and nothing is written over the file until you try again or set it aside (it's kept as `logins.anvil.unreadable`) from `anvil://settings/logins`. Saving is offered only after a form with a password is posted from an `https` page to the same host, and a login fills only on an `https` page of exactly that host, when you press Ctrl+Shift+K. Plain `http` pages never get one, even when that site is allowed plain HTTP. `anvil://settings/logins` lists host and username; a password is shown only when you ask for it there, and the page key is needed for that and for every change. Passwords are not logged. There is no master password. Clearing all profile data deletes `logins.anvil` too.
- Encrypted video samples are AES-128-CTR from `anvil-cipher`. CTR has no tag.
- Parsers across `crates/` and `engines/go/anvil-*` in this repository reject oversized input.
- `anvil-net` links Brave Browser's unmodified open-source `adblock-rust` crate (`adblock::Engine`, MPL-2.0) to evaluate network requests against Adblock Plus / uBlock Origin filter rules, `@@` exceptions, `$important`, `$third-party`, resource-type masks, `$redirect` web-accessible surrogates, `$removeparam` tracking query parameter stripping, and cosmetic element hiding (`##` and `#@#`), with per-site Shields Up/Down controls on `anvil://shields` (`anvil://security`).
- SHA-256 (`sha256-` via `anvil-cipher`) and SHA3-256 (`sha3-256-` via `anvil-pqc`) are used for Subresource Integrity checks, and SHA-256 is used for download records.
- PNG chunk checksums are checked in `anvil-image`.
- Stylesheet `width`, `height`, `max-width`, offsets, `margin`, `padding`, `border-width`, `border-radius`, `font-size`, and `line-height` resolve `px`, `%`, `em`, `rem`, `ch`, `vw`, `vh`, `vmin`, `vmax`, `calc()`, and CSS Values Level 4 math functions (`round()`, `mod()`, `rem()`, `sin()`, `cos()`, `tan()`, `asin()`, `acos()`, `atan()`, `atan2()`, `pow()`, `sqrt()`, `hypot()`, `log()`, `exp()`, `abs()`, `sign()`, `min()`, `max()`, `clamp()`), alongside `@font-face`, `font-family` (`Sans`, `Serif`, `Mono`), `text-transform`, `letter-spacing`, `word-spacing`, `text-decoration: underline | line-through`, `::before` and `::after` generated content pseudo-elements (`content: "..." | attr(...)`), `radial-gradient(...)`, `conic-gradient(...)`, `repeating-linear-gradient(...)`, `repeating-radial-gradient(...)`, `backdrop-filter: blur(...)`, `filter`, per-side border colors, `outline`/`outline-offset`, `object-fit`, `overflow: auto | scroll` containers, `text-overflow: ellipsis`, `overflow-wrap: break-word` / `word-break: break-all`, CSS Logical Properties (`inline-size`, `block-size`, `padding-inline*`, `padding-block*`, `margin-inline*`, `margin-block*`, `inset-inline*`, `inset-block*`, `border-inline*`, `border-block*`) and standalone `translate`, `scale`, and `rotate` properties. Custom properties (`--*` and `var()`, including recursive `var(--missing, fallback)` recovery and inheritance across Shadow DOM boundaries) stop after 8 nested substitutions. `@supports` feature queries (with selector/declaration fault recovery), `@scope (<root>) to (<limit>)` boundary evaluation, `@container` size queries (`min-width`, `max-width`, and range comparisons `width >= 300px` / `width <= 600px`), `@layer`/`@starting-style` rule blocks, and Selectors Level 4 (`:is()`, `:where()`, `:not()`, `:has()`, `:host`) are evaluated in `anvil-style` and the in-tree `engines/prism` engine. Any other unit becomes `auto`. A percentage height is `auto` when the containing block height is not set. `flex-grow` only distributes positive free space.
- Script `fetch()` is same-origin only. The Rust interpreter performs it. A cross-origin URL returns status 403 and does not connect. The numeric compiler does not perform `fetch()`. The interpreter keeps at most 2.5 MiB of a response body. `anvil-net` still stops at its raw and decompressed caps.
- WebAssembly 1.0 (`\0asm` version `1`) modules are validated and executed inside `anvil-script::wasm` with a 160 MiB (`2,560`-page) linear memory cap, a `5,000,000`-instruction execution budget (`MAX_WASM_STEPS`), and a `640`-frame call depth cap (`MAX_WASM_CALL_DEPTH`). Out-of-bounds memory accesses, division by zero, and step/depth exhaustion trap cleanly without panicking.
- `anvil://settings/exchange` writes and reads `anvil-exchange-v1` files, plain JSON with bookmarks, the addresses of open tabs, the theme, search engine, zoom, and HTTPS-only. It is off until you turn it on there. History goes in only when you tick it. Cookies, `localStorage`, downloads, and saved logins never go in, and an import leaves them and any other unknown key out with a warning. A file is written or read only at the path you type, after you press the button, with the page key; nothing is written in the background and nothing is sent over the network. An import adds bookmarks, takes the theme, engine, and zoom, can turn HTTPS-only on but never off, and lists tabs instead of opening them. Only `http`, `https`, and `anvil://` addresses without a query are taken, either way.
- `Ctrl+P` writes a PDF 1.4 file into the downloads folder (`pdf.rs`). Each sheet is a picture of the page at 96 pixels per inch, letter size (8.5 by 11), at most 40 sheets and 48 MiB. Reader Mode saves the reader view. The file is not uploaded. Text in it is not selectable. The `anvil pdf` command writes the same kind of file.
- A tab keeps at most 32 history entries (`MAX_TAB_HISTORY`). Leaving a page freezes that copy in the window: its videos pause and `pagehide` runs with `persisted` set. Back restores it and runs `pageshow`. Entries past 32 are dropped, oldest first.
- Unmuted `play()` without a click or key is rejected (`NotAllowedError`). Muted play, and volume 0, is allowed, including muted `autoplay` when a video loads.
- YouTube, Gmail, Facebook, Instagram, X, Outlook, TikTok, LinkedIn, Reddit, other social hosts, and bank and payment hosts load through the normal HTTP path. External scripts on those hosts are not fetched. A script runs only when the code outside its quotes is at most 256 KiB. A `script` type that is not JavaScript is not executed. No API key is stored.
- Google Maps, OpenStreetMap, and `anvil://maps` are not loaded as those sites. This process fetches nine tiles at once and paints one bitmap. Tiles already fetched stay in memory for later pan and zoom. They are not written to the profile. OpenStreetMap comes from `tile.openstreetmap.org`. ArcGIS imagery, streets, and topo come from `server.arcgisonline.com`. A `webmap=` item is read from `arcgis.com` and one feature layer is queried, at most 80 features. A `token` on the address is sent only to an ArcGIS host and is not saved. OpenStreetMap hosts use the longer User-Agent. No maps API key is stored.
- Numeric x86-64 machine code. A `while` or `for` whose body is only numbers is compiled and the numbers are written back into the page script. The same loop may assign `document.getElementById("...").textContent` to a number. That one write calls back into the page. Other property reads stay on the interpreter. A whole script with no DOM, `fetch()`, or storage can take the numeric path. On Linux the page is mapped writable, filled, then marked read and execute, and calls use the System V argument order. On Windows the page is allocated with `VirtualAlloc`, and calls use `rcx`, `rdx`, and `xmm2`, with 32 bytes of shadow space. The caller owns the VM context. The worker process has its own context. This is not a general compiler.

## What is not on

- A system accessibility bridge. `F10` or `Alt+Shift+T` draws a focus ring and a name in the window. Those names are not reported through UI Automation or AT-SPI. Rows inside the app menu, the site card, and the downloads card are not reached with the arrow keys.
- The real YouTube player bundle, the Gmail inbox application, the Facebook feed, the current Reddit application, and bank web apps. Those are large script bundles that normal page loads do not run. The HTML document is still loaded. `ScriptRuntime::eval_script` automatically routes ES2022+ DOM scripts within the 256 KiB script size cap through the in-tree `engines/cinder` engine (both the `cinder::vm::Vm` register bytecode VM, with its `ElementsKind` dense array lattice, `OneByte` Latin-1 and `Sliced` strings, 256-entry megamorphic stub cache and global ICs, fused peephole superinstructions, nursery minor GC `collect_minor`, and live `CinderDomHost` bindings via `eval_with_cinder_engine`, and the C++20 `CinderVM` with its 64 MiB heap budget, native x86-64 baseline JIT for arithmetic, control flow, and object/array IC ops, hierarchical DOM seeding `seedHostNode` / `seedHostAttr`, live DOM/storage/location/`<canvas>` mutation replay `exportDomMutationRows`, live `DOMParser.parseFromString` subtree adoption `adoptNode`/`importNode`, `document.adoptedStyleSheets` / `CSSStyleSheet.replaceSync()` sync, interactive `click`/`input`/`submit`/`keydown` event replay `dispatchHostEvent`, and automatic C++ VM memory release at the end of page script execution), and `anvil-script` also exposes `eval_webapp_with_cinder` and `eval_webapp_with_live_dom_bridge`, but external script bundles on those large social and bank hosts are still not fetched or executed. A YouTube watch page adds a player built from YouTube's published JPEG frames, or a storyboard sheet when the page includes one. That player is not a live H.264/AV1/VP9 stream. After Gmail's HTML sign-in form is posted, Google's own page says JavaScript is required. Reddit stays on the address you opened, including `www.reddit.com`, and is not sent to `old.reddit.com`. Requests to a Reddit host use a longer User-Agent that names this browser. A network-policy 403 is Reddit's, and this browser does not bypass it. No password is stored for a bank or a social site unless you save one on `anvil://settings/logins`.
- Full H.264 (`avc1`) CABAC/CAVLC bitstream decoding, every optional third-party VP9/AV1 entropy/transform mode, or GPU hardware video decoding. `anvil-video` 0.11.0 (`v.11`) implements RFC 6386 VP8 boolean-coded intra/inter frames, clean-room VP9 uncompressed headers + 8x8 DCT/IDCT intra/inter frames + superframe index, clean-room AV1 (`AOMedia OBU` sequence/frame headers + 8x8 DCT/IDCT intra/inter + CDEF filter), and RFC 6716 Opus range-coded SILK/CELT frames, alongside its `AVID` (`NV12`/BT.709) and `ADCT` (8x8 integer DCT/IDCT + 16x16 macroblock motion compensation) codecs, `AudioOutputBridge` master audio clock A/V drift tracking and streaming PCM16 ringbuffer, and `fMP4` (`moof`/`traf`/`trun`) and `WebM`/`EBML` container muxers/demuxers, while Annex-B H.264 helpers wrap `ADCT` payloads inside their headers. The Windows Media Foundation / D3D11 Video and Linux VA-API probes only check whether system DLLs or `/dev/dri` nodes exist; all video decoding runs on the CPU.
- A full-page GPU text and image rasterizer. In default page rasterization (`paint_span`), `anvil-raster` coalesces contiguous vector and compositor display items (opaque rects, rounded-rect box fills and opaque borders, blurred box shadows, unrounded and rounded linear gradients, clips, and fixed-scroll offsets) into batched `GpuSceneBatch` command buffers executed via `anvil_gpu::Compositor::execute_scene_batch` (with `anvil-gpu` 0.12.0 hardware-accelerated rounded `SolidRect` and `RoundedGradient` SDF passes, and explicit `build_gpu_scene_batch` / `rasterize_gpu_batch`), which runs on the GPU (Direct3D 11 on Windows, OpenGL 3.3 core on Linux) when the startup self-test passes bit-for-bit against the CPU, and falls back to the CPU otherwise. Default page rasterization still flushes and draws text (with `anvil-ttf` 0.11.0 multi-family `Sans`/`Serif`/`Mono` and bold/italic styled glyph synthesis, 4-bin `0.25 px` horizontal subpixel phase glyph caching `cached_rasterize_glyph_phased`, pairwise kerning, and gamma-correct linear-space alpha blending `set_glyph_pixel_gamma_correct`), translucent rects, and ordinary images on the CPU path (with bounded LRU glyph and image caches). On Windows, `present.rs` uploads the finished RGBA framebuffer directly to the Direct3D 11 SwapChain (using zero-copy full-frame upload and `D3D11_BOX` dirty-row partial upload on chrome-only redraws); on Linux, `present.rs` probes EGL/OpenGL 3.3 Core (`anvil_gpu::probe_hardware`) and converts full frames or dirty scanline bands (`copy_bgra_rows_top_down`) with SSE2 into the `mmap`ped Wayland `wl_shm` shared-memory buffer or X11 `XPutImage`.
